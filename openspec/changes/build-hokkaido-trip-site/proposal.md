# 北海道小旅行行程網站

## Why

行程資料散在一份 Google 試算表的六個頁籤裡，彼此有關聯卻無法一起閱讀；既有的 `design_handoff_hokkaido_trip/hokkaido-trip.html` 是把行程手寫進程式碼的設計原型，行程一改就得改程式。

這趟旅行是 2026/12/25 – 2027/01/03，出發前還有數個月，行程會持續變動。需要一個公開網址就能打開、資料永遠跟著試算表走、也能分享給同行者的網站。

## What Changes

- 新增一個部署於 GitHub Pages 的單頁靜態網站，開頁時即時抓取試算表，不需建置流程
- 行程路線改為由資料推導：同一天相鄰兩列即構成一段行程，不再手寫 `legs`
- 座標與景點介紹移入獨立的 `places.json` 地名簿；試算表新增的未知地點改以地理編碼補上，查不到也不中斷渲染
- 新增內容區塊：封面、全行程總覽、五座城市、吃什麼、住哪裡、花多少、行前準備、導覽列
- 全站只保留**一個**地圖實體。「全程」成為日期時間軸的第一列與載入預設畫面，取代原本另立的總覽地圖
- **BREAKING**：原型中手寫的 `DAYS`、`LEG_SPOT`、`WIKI`、`OWN` 資料結構全數移除，改由試算表與 `places.json` 供應
- 敏感欄位（訂位代號等）採**欄位白名單**，永不進入前端資料結構

## Capabilities

### New Capabilities

- `trip-data-sync`: 從六個試算表頁籤即時抓取、解析與建模，含欄位白名單、跨頁籤關聯、逐頁籤的失敗退路
- `itinerary-map`: 單一地圖，含「全程」與單日兩種模式、單日動畫播放、地名簿與未知地點地理編碼
- `trip-overview`: 封面（含出發倒數）、全行程數字帶與每日圖例、五座城市區塊
- `dining-guide`: 餐飲區塊，含北海道拉麵三大天王與預約狀態
- `lodging-guide`: 住宿區塊，含晚數計算、費用與訂房狀態，以及跨頁籤補齊缺漏
- `budget-summary`: 費用區塊，含雙幣別換算、分類佔比，以及未填資料的誠實呈現
- `prep-checklist`: 行前準備區塊，呈現待辦清單完成度
- `site-shell`: 導覽列、頁面骨架、響應式斷點、靜態部署與外部服務署名

### Modified Capabilities

（無。`openspec/specs/` 目前為空，此為首個變更。）

## Impact

**新增**
- `index.html`、`app.js`、`config.js`、`places.json`、`photos/`
- GitHub 儲存庫與 GitHub Pages 設定

**沿用**
- `design_handoff_hokkaido_trip/` 保留為設計參考，其視覺 token、地圖互動邏輯與 18 張照片是本次實作的來源

**外部依賴**
- Google 試算表 CSV 匯出端點（已實測回應 `Access-Control-Allow-Origin: *`）
- Leaflet、OpenStreetMap 圖磚（須保留 attribution）
- OSRM demo 道路路徑、Nominatim 地理編碼——皆為無服務保證的公共服務，兩者都必須有不阻塞畫面的退路

**資料面**
- 試算表本身存在五項落差（行程只填 7/10 天、機票與 JR Pass 人數不一致、成吉思汗店名矛盾、住宿頁籤缺兩間、照片對照表兩筆對不上）。網站如實呈現，不自行修正
- 年份不一致已由使用者於 2026-08-14 修正，六個頁籤現皆為 2026

**隱私**
- 網站部署於公開網址，而交通頁籤含訂位代號。欄位改採白名單，新增欄位預設不顯示

# 實作任務

階段一（1–5 節）完成時網站即可上線運作；階段二（6–11 節）逐步加上內容區塊。

## 1. 專案骨架

- [ ] 1.1 建立 `index.html`、`app.js`、`config.js` 三個檔案與空的 `photos/` 目錄
- [ ] 1.2 由原型搬入設計 token（色彩、字體、圓角）與字型載入，確認頁面底色與字體正確
- [ ] 1.3 在 `config.js` 定義試算表 ID、六個頁籤 GID、匯率初值 `0.21`
- [ ] 1.4 建立本機開發用的靜態伺服器指令，確認可用 `http://localhost` 開啟（`file://` 會擋住 `fetch`）

## 2. 資料層：抓取與解析

- [ ] 2.1 實作 CSV 抓取函式，並行取得六個頁籤
- [ ] 2.2 實作 CSV 解析（需正確處理引號內的逗號與換行——費用規劃頁籤的備註欄含多行內容）
- [ ] 2.3 為六個頁籤各自定義欄位白名單，並確認「交通」頁籤的 `訂位 / 備註` 欄不在其中
- [ ] 2.4 實作單一頁籤失敗的隔離：該區塊顯示錯誤與重試按鈕，其餘區塊照常
- [ ] 2.5 實作全部抓取失敗的錯誤畫面，列出可能原因
- [ ] 2.6 驗證：以瀏覽器開發者工具搜尋訂位代號字串，確認不存在於 DOM 與任何全域變數

## 3. 資料層：行程建模

- [ ] 3.1 由「行程規劃」頁籤依日期分組，產生每日的景點清單
- [ ] 3.2 由同日相鄰兩列推導路線段，當日第一列只產生景點
- [ ] 3.3 實作交通方式關鍵字分類（jr / drive / bus / tram / walk / flight），依規格的判斷順序
- [ ] 3.4 處理特殊列：地點為空、單欄多地點、Check-in 判定為住宿
- [ ] 3.5 實作跨頁籤的月-日關聯，並在偵測到年份不一致時產生提示

## 4. 地名簿

- [ ] 4.1 由原型 `P` 物件搬出 28 筆座標，建立 `places.json`
- [ ] 4.2 由原型 `DAYS[].spots[].d` 搬出景點介紹文字填入 `desc`
- [ ] 4.3 補齊原型未涵蓋的 8 個地點座標
- [ ] 4.4 將 18 張照片由 `design_handoff_hokkaido_trip/uploads/` 搬到 `photos/` 並改為有意義的檔名，更新 `photo` 欄
- [ ] 4.5 為兩筆命名不符的照片建立別名（成吉思汗大黑屋、薄野民宿）
- [ ] 4.6 為三家拉麵店標記 `ramen` 流派（醬油／鹽味／味噌）
- [ ] 4.7 實作未知地點的 Nominatim 查詢，含每秒一次的速率限制與 `localStorage` 快取
- [ ] 4.8 實作查詢失敗的降級：地點仍入卡片列表、不上地圖，並在畫面列出待補清單

## 5. 地圖與逐日行程

- [ ] 5.1 建立單一 Leaflet 實體，套用原型的圖磚色調與 attribution
- [ ] 5.2 由資料渲染日期時間軸，首列為「全程」，末列為未規劃區間
- [ ] 5.3 實作「全程」模式：七天路線各自上色、縮放至全程範圍、不播放動畫
- [ ] 5.4 移植原型的單日渲染：路線、轉車節點、景點標註、住宿標籤
- [ ] 5.5 移植原型的單日動畫：載具移動、鏡頭跟隨、抵達彈卡、卡片同步高亮
- [ ] 5.6 移植 OSRM 道路路徑取得與平滑折線退路，確認退路不阻塞渲染
- [ ] 5.7 實作載入預設為「全程」、2.6 秒後自動進入 Day 1 連播；使用者點選任一日期即停止連播
- [ ] 5.8 實作切換日期時中止進行中的動畫與未完成請求
- [ ] 5.9 渲染當日景點卡片列表
- [ ] 5.10 驗證：頁面中 `.leaflet-container` 數量恰為 1

## 6. 部署

- [ ] 6.1 推上 GitHub 並啟用 GitHub Pages
- [ ] 6.2 於公開網址驗證：地圖、動畫、資料載入皆正常（HTTPS 下的跨網域抓取）
- [ ] 6.3 確認 OpenStreetMap attribution 可見

- [ ] 7.1 實作吸頂導覽列與區塊跳轉
- [ ] 7.2 實作全幅封面：大圖、標題、日期區間、城市清單

## 8. 全行程總覽

## ADDED Requirements

### Requirement: 即時抓取試算表六個頁籤

系統 SHALL 於頁面載入時，直接由瀏覽器向 Google 試算表的 CSV 匯出端點抓取六個頁籤，不經任何後端代理。

端點格式為 `https://docs.google.com/spreadsheets/d/{ID}/export?format=csv&gid={GID}`，該端點回應 `Access-Control-Allow-Origin: *`。

| 頁籤 | GID |
|---|---|
| 行程規劃 | `0` |
| 餐飲 | `126273833` |
| 住宿 | `1315714937` |
| 交通 | `1509364219` |
| 費用規劃 | `1572357344` |
| 待辦清單 | `199634433` |

試算表 ID 與各頁籤 GID SHALL 定義於 `config.js`，不得散落於程式碼各處。

#### Scenario: 六個頁籤全部抓取成功

- **WHEN** 使用者開啟網頁且網路正常
- **THEN** 系統並行抓取六個頁籤，並在全部解析完成後渲染所有區塊

#### Scenario: 使用者更新試算表後重整

- **WHEN** 使用者在試算表新增、刪除或重新排序任一列，並重新整理網頁
- **THEN** 畫面反映最新內容，且不需要修改任何程式碼

### Requirement: 單一頁籤失敗不影響其他區塊

系統 SHALL 讓每個頁籤的抓取失敗只影響其對應區塊，其餘區塊照常渲染。

#### Scenario: 費用頁籤抓取失敗

- **WHEN** 「費用規劃」頁籤回應非 2xx 或逾時
- **THEN** 「花多少」區塊顯示錯誤訊息與重試按鈕
- **AND** 逐日行程、住宿、餐飲等其他區塊正常顯示

#### Scenario: 全部頁籤皆失敗

- **WHEN** 所有頁籤都無法抓取
- **THEN** 系統顯示錯誤訊息，並列出可能原因（試算表未公開、裝置離線）

### Requirement: 敏感欄位採白名單

系統 SHALL 以明確列舉的欄位白名單讀取資料，未列於白名單的欄位不得進入任何前端可讀的資料結構，亦不得渲染至畫面。

網站部署於公開網址，而「交通」頁籤的 `訂位 / 備註` 欄含訂位代號；訂位代號搭配乘客姓氏在多數航空公司系統中足以查詢甚至變更訂位。

#### Scenario: 交通頁籤含訂位代號

- **WHEN** 系統解析「交通」頁籤
- **THEN** `訂位 / 備註` 欄不被讀入資料模型
- **AND** 該欄內容不出現在 DOM、`window` 物件或任何 JavaScript 變數中

#### Scenario: 使用者日後在試算表新增欄位

- **WHEN** 試算表新增一個白名單未涵蓋的欄位
- **THEN** 該欄位預設不顯示，且系統不因此報錯

### Requirement: 由相鄰列推導行程路線

系統 SHALL 將「行程規劃」頁籤的每一列視為「一個景點 + 抵達該景點的那一段交通」，並由同一天內相鄰兩列推導出行程路線段（leg）。

當日第一列沒有前一列，SHALL 只產生景點、不產生路線段，跨日移動不畫線。

#### Scenario: 推導單日路線

- **WHEN** 某日有 N 列資料
- **THEN** 系統產生 N 個景點與 N-1 段路線
- **AND** 每段路線的交通方式取自後一列的「交通工具」欄

### Requirement: 交通方式分類

系統 SHALL 依「交通工具」欄的關鍵字判斷交通方式，判斷順序由上而下、先命中者為準。

| 關鍵字 | mode | 顏色 |
|---|---|---|
| `JR`、`特急`、`特級`、`本線`、`Rapid Airport` | `jr` | `#0e7ad4` |
| `開車`、`租車` | `drive` | `#f4622e`（虛線） |
| `巴士`、`接駁車` | `bus` | `#12a97a` |
| `市電`、`地下鐵` | `tram` | `#f0ad2a` |
| `步行` | `walk` | `#f0ad2a` |
| 航班（如 `台灣虎航`） | `flight` | 不畫線 |
| 空值或無法判斷 | `walk` | 預設 |

#### Scenario: 欄位含多個交通工具

- **WHEN** 「交通工具」欄為 `Rapid Airport、JR 函館本線 (普通 / 快速)`
- **THEN** 系統依先命中者為準，判定為 `jr`

#### Scenario: 交通工具欄為空

- **WHEN** 某列的「交通工具」欄為空
- **THEN** 系統以 `walk` 作為預設，且不中斷渲染

### Requirement: 跨頁籤日期關聯與跨年排序

系統 SHALL 以**完整日期**關聯跨頁籤資料並排序。若某列以完整日期找不到對應，SHALL 退回以月-日比對，並在畫面顯示年份不一致的提示。

系統 SHALL NOT 覆寫試算表中的年份。

行程跨越年界（2026/12/25 – 2027/01/03），因此排序 MUST 使用完整日期；僅以月-日排序會將 `01-01` 排在 `12-25` 之前。

#### Scenario: 各頁籤年份一致

- **WHEN** 所有頁籤的日期皆為 `2026-12-29`
- **THEN** 系統以完整日期成功關聯，且不顯示年份提示

#### Scenario: 頁籤間年份不一致

- **WHEN** 「行程規劃」為 `2026-12-29` 而「餐飲」為 `2025-12-29`
- **THEN** 系統退回以 `12-29` 關聯兩筆資料
- **AND** 畫面顯示一則提示，說明頁籤間年份不一致

#### Scenario: 行程跨越年界

- **WHEN** 資料同時含 `2026-12-31` 與 `2027-01-01`
- **THEN** `2027-01-01` 排序於 `2026-12-31` 之後
- **AND** 兩者被視為相鄰的兩天

#### Scenario: 跨年日期誤填為同一年

- **WHEN** 使用者將 1/1 的行程填為 `2026-01-01` 而非 `2027-01-01`
- **THEN** 系統顯示日期異常提示，指出該列早於行程起始日

### Requirement: 特殊列的處理

系統 SHALL 妥善處理資料不完整或格式特殊的列，且不中斷渲染。

#### Scenario: 地點欄為空

- **WHEN** 某列的「地點」欄為空（例如 `12/30 18:00 函館市 (空) 晚餐`）
- **THEN** 該列不產生地圖標記
- **AND** 該列仍以「待定」形式出現在當日卡片列表

#### Scenario: 單一欄位含多個地點

- **WHEN** 「地點」欄為 `大通公園、札幌電視塔`
- **THEN** 系統視為單一地點，座標取第一個

#### Scenario: 判定住宿

- **WHEN** 某列的「活動內容」含 `Check-in`
- **THEN** 該景點標記為住宿，並以住宿色 `#7a5cc4` 呈現
